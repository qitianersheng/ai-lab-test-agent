## 🛠️ 第一阶段：项目深度扫描（分析规范）

你在开始撰写知识地图前，必须结合 Claude Code 的工具链（如使用 grep、查看文件树、检索配置文件等），完成以下维度的自主分析：
1. **技术栈大盘点**：通过分析构建配置文件（如 package.json, pom.xml, go.mod, Requirements.txt 等）以及基础镜像配置（Dockerfile），精准锁定制定的开发语言、核心框架、数据库、中间件及第三方关键依赖版本。
2. **架构拓扑推导**：通过分析项目目录结构、调用链路、路由配置（Router）、微服务配置文件（如 k8s yaml, docker-compose）以及网关配置，理清系统的分层架构（如 MVC、微服务、DDD 领域驱动设计等）与边界。
3. **核心接口/路由提取**：全局搜索暴露的 HTTP/RPC 接口。重点提取最核心的业务路由、鉴权机制、输入输出核心数据结构（DTO）。
4. **数据模型（ER）推导**：检索项目中的实体类定义（Entities/Models）、数据库初始化脚本（SQL）、或 ORM 映射文件，梳理出最核心的核心业务表/集合及其关联关系。

## 第二阶段：知识地图输出规范

请在项目指定目录（默认为项目根目录）下，生成名为 `SYSTEM_KNOWLEDGE_MAP.md` 的 Markdown 文档。文档必须严格包含以下模块，且内容必须基于项目真实代码，严禁虚构或使用占位符：

### 1. 📑 系统概述与技术栈拓扑
- **系统核心定位**：用 2-3 句话精准概括该系统解决的核心业务问题。
- **技术栈清单**：使用清晰的 Markdown 表格，列出：【分层（前端/后端/数据/基础设施） | 核心技术/组件名称 | 版本号 | 作用描述】。

### 2.  系统架构与分层设计
- **目录结构与架构映射**：梳理关键目录结构，并对每个核心文件夹的架构职责（如：`domain/` 存放核心业务逻辑，`infrastructure/` 负责外部对接）进行文字映射说明。
- **架构图（Mermaid 渲染）**：必须使用 Mermaid 语法绘制至少一张系统架构图或数据流向图，清晰展现客户端、网关、应用服务、数据库及外部三方服务的交互逻辑。

### 3. 🔌 核心接口与服务契约
- **核心业务链路接口**：挑出系统最核心的 5-10 个业务接口（如：用户认证、核心下单、数据上报等），列出：【接口名称 | 请求方法 | 路由路径 | 核心入参/出参关键字段说明】。
- **关键依赖/三方服务**：如果系统调用了外部系统（如支付网关、短信平台、底层自研中台），清晰列出对接方式（HTTP/RPC）及核心调用场景。

### 4. 核心数据模型（ER 关系）
- **核心实体/表结构**：列出核心业务对应的实体或表（不超过5个），简述其承载的业务数据。
- **实体关系（Mermaid ER 图）**：使用 Mermaid 的 `erDiagram` 语法，绘制出核心表之间的 1:1、1:N 关联关系，帮助开发者快速建立全局数据认知。
