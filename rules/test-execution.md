# 测试执行规范（步骤 2 · AI 实时驱动 Playwright）

**目标**：把已批准的测试用例**直接执行**——通过 Playwright MCP 浏览器工具实时驱动浏览器，逐条用例满足前置→执行操作→对照「预期结果」判定四态，捕获证据。**严禁在执行阶段修改任何业务源码与配置**。

> **V0.11 变更**：需登录态时**先找持久化登录态** `AI_LabTest/.auth/{env}.{sanitize(key)}.storageState.json`（**不是** environments.json）；无则登录（environments.json 账号 / 浏览器手动登录，全程不碰用户密码）并把会话**存成 storageState 复用**；仍不行才判 blocked。见 §1「登录态建立」。
> **V0.9 变更**：执行**以当前 `{任务}-testcase.md` 为准**——重新读文件、有几条跑几条；用户手工增删用例（如 50→3）照当前文件执行，不补已删、不沿用旧版（见 §1）。
> **V0.3 变更**：不再生成 `.spec.ts`、不再 `npx playwright test`。改为 AI 持浏览器工具实时操作被测系统，自判四态，落盘结构化结果。本规范同时被桌面应用的执行引擎注入到 AI 提示中。

**入口硬校验**：`/AI_LabTest/testCase/{任务}-testcase.md` 必须存在且非空，否则中断并退回步骤 1。

## 0. 环境预检（执行前强制）

### 0.0 范围边界（铁律）

| 环境 | 是否支持 | 说明 |
|---|---|---|
| **local** | ✅ 支持 | 本地开发环境 |
| **SIT** | ✅ 支持 | 集成测试环境 |
| **UAT** | ❌ **不支持** | 业务验收阶段，必须由业务方手工执行 |
| **生产（prod）** | ❌ **永不支持** | 自动化绝对不可触达生产 |

`environments.json` 的 `allowedEnvs` 字段是唯一可信白名单（默认 `["local", "sit"]`）。**禁止**对 `uat` / 生产 / 任何不在白名单的值执行。

### 0.1 询问用户选定环境（强制）

用 `AskUserQuestion`：

> 本次测试目标环境？
> - 本地（local）
> - SIT

**禁止默认走 local 不问用户**。**禁止呈现 UAT 选项**；用户主动要求测 UAT 必须拒绝并解释「UAT 由业务方负责」。

### 0.2 校验环境配置完整性

读 `/AI_LabTest/environments.json`：

| 字段 | 是否必须 | 缺失时行为 |
|---|---|---|
| `frontendBaseUrl` | 是 | 为 `TBD` → 引导用户填写并更新 `environments.json` |
| `apiBaseUrl` | 推荐 | 为 `TBD` → 仅警告，不阻塞 |
| 测试账号（`accounts`/`testAccount`） | 是 | 为 `TBD` → 引导用户填写 |

首次用 SIT 时，引导用户提供前端 URL / API URL / 账号，写回 `environments.json` 并提示「下次无需重填」。

### 0.3 被测地址探活（强制）

对 `frontendBaseUrl` 做一次可达性探测（GET，有响应即视为站点在跑，含 3xx/4xx）：

| 结果 | 行为 |
|---|---|
| 可达 | ✅ 进入执行 |
| 连接被拒 / 超时 / DNS 失败 | ❌ **中断**，提示：local 请先启动前端服务 / SIT 请检查 VPN 与地址，**不要白跑一整轮**（不可达时每条用例都会失败且很慢） |

> 桌面应用的执行引擎会自动完成本探活；在目标项目里用 Claude CLI 执行时，由 AI 用 `curl`/请求工具完成。

### 0.4 选执行模式

| 模式 | 含义 |
|---|---|
| **可见（有头）** | 弹出可见浏览器窗口，操作过程肉眼可见，便于观察/演示 |
| **后台（无头）** | 不弹窗，仅产出四态结果，更快 |

用户未指定 → 默认后台无头。

## 1. 执行方式（用 Playwright MCP 浏览器工具）

### 1.0 唯一执行引擎（铁律 · 不可违反）

- **唯一方式**：Playwright MCP 的 `browser_*` 工具（实际名可能为 `mcp__playwright__browser_*`）实时驱动浏览器。
- **绝对禁止**：编写或运行任何测试脚本（`.spec.ts`、`test(...)`、`npx playwright test`）、独立 node / python 浏览器脚本、新建 `playwright.config.*`。
- **即使检测到 Playwright（npm 包 / 二进制）已安装，也绝不走脚本路径** ——「Playwright 可用 ≠ 可以写脚本」。脚本不是本框架的执行手段。
- **`browser_*` 不可用时**：立即**硬停止**，判本轮 `blocked`（根因：Playwright MCP 未启用），引导用户启用 MCP（见 `commands/execute.md`「启用 Playwright MCP」），**绝不**用脚本兜底、绝不“变通”绕过。

执行**不依赖任何 spec 文件**。AI 用以下浏览器工具直接操作被测系统（工具名以 `browser_` 开头，由 Playwright MCP 提供）：

| 工具 | 用途 |
|---|---|
| `browser_navigate` | 打开/跳转页面（用 `frontendBaseUrl` 拼相对路径） |
| `browser_snapshot` | 读取页面可访问性结构（定位元素、确认真实状态的首选） |
| `browser_click` | 点击元素 |
| `browser_type` / `browser_fill_form` | 输入文本 / 批量填表 |
| `browser_select_option` | 下拉选择 |
| `browser_wait_for` | 等待文本出现/消失或超时 |
| `browser_take_screenshot` | 截图留证（保存到执行引擎指定的 output-dir） |
| `browser_navigate_back` / `browser_press_key` | 后退 / 键盘操作 |

**最新文件为准（铁律）**：执行前**重新 Read 当前 `{任务}-testcase.md`**，**文件里现有几条就跑几条**。用户在 Step 1 之后手工增删 / 裁剪用例（如生成 50 条、删成 3 条）一律照**当前文件**执行——不补回已删用例、不沿用旧版本快照、不从需求重新生成补齐；本轮用例条数取自当前文件，run.json 的 `tests[]` 只含当前文件里的用例。

**逐条用例的执行循环**：

1. 读用例表格行的「前置条件 / 测试操作 / 预期结果 / 断言」（「需求引用」列含 预期依据，供可追溯）。
2. 满足前置：需要登录态的用例，按下文「登录态建立」流程登录建立会话。
3. 执行测试操作：按用例步骤在真实页面上操作；用 `browser_snapshot` 观察真实结构，不要凭空臆测元素。
4. 对照「预期结果」判定四态（见 §2）。
5. `browser_take_screenshot` 截一张图留证。

**登录态建立（需要登录的用例 · 铁律：先找持久化登录态、无则登录并存盘复用、不直接判 blocked）**：

1. **先找持久化登录态文件**（**先查这里，不是 environments.json**）：`{项目目录}/AI_LabTest/.auth/{env}.{sanitize(key)}.storageState.json`——`{env}`=local/sit；`key`=该登录态对应的账号/角色键（默认 `testAccount.role`，多角色各用各自 role/username）；`sanitize(key)`=转文件名安全（去空格 / 斜杠 / 特殊字符）。
2. **文件存在** → 把该 storageState（cookies + localStorage）加载进浏览器上下文，**免登录**建立会话；`browser_snapshot` 确认有效（受保护页可达、未被弹回登录页）。**已过期**（被弹回登录）→ 当作未找到，走第 3 步重建。
3. **文件不存在 / 已过期** → 登录，并**把登录后的会话存成上面的 storageState 文件**（供后续用例与后续运行复用）：
   - 查 `environments.json` 当前环境 `testAccount`：**有账号** → 用它自动登录；
   - **无账号 / 为空 / 仍是 `TBD`** → **不直接判 `blocked`**，用 `AskUserQuestion` 二选一：
     - **① 配置测试账号**：收集 username / password 写入 `environments.json` 的 `testAccount`（**只写 environments.json，绝不写进任何 md / log / 报告**），再自动登录。
     - **② 浏览器手动登录**：切**可见（有头）模式**，`browser_navigate` 打开登录页，提示「请在弹出的浏览器里自行登录（账号密码 / SSO / 2FA 皆可），登录完成后回复『继续』」。**登录期间绝不关闭弹出的浏览器**：不 `browser_close`、不导航离开登录页、不中断会话——保持窗口打开、停下来等用户回复『继续』（输密码 / 过 2FA 要时间，别因"没动作"就关窗或判超时）。用户回复后 `browser_snapshot` 确认已进入登录态。**全程不索取、不记录用户密码。**
   - 登录成功后 → **导出当前会话存盘**到 `AI_LabTest/.auth/{env}.{sanitize(key)}.storageState.json`；该浏览器**全程保持打开**复用会话、执行中途不主动关闭，到本轮结束才自然关闭（或交用户自行关闭）。
4. `.auth/` 目录含会话令牌，**敏感**：已在 `gitignore.snippet` 忽略，**绝不**把该文件或其中 token 写进任何报告 / log。
5. 账号登录失败 / 会话过期重试仍不行（含 §2.1 的 401）→ 判 `blocked`（根因：登录态无法建立）。

> **MCP 能力前提**：加载 / 保存 storageState 需 Playwright MCP 支持（`--storage-state` 或会话存取能力）。运行的 MCP 若不支持持久化 → 退化为「每轮登录一次、不缓存」，流程其余不变。

**定位与判断纪律**：

- 元素定位以 `browser_snapshot` 的真实可访问性结构为准（角色/可见文本/标签），不要臆造选择器或文案。
- 断言对应真实可观察结果：可见文本、URL、元素出现/消失、列表条数等——以页面实际表现为准。
- 判定必须有真实证据（截图 / 快照 / URL）支撑，**不要为了变绿放水**。

## 2. 四态判定决策树

**结果四态**：

| 状态 | 含义 |
|---|---|
| `pass` | 路径成立，预期可观察结果全部出现 |
| `fail` | 路径存在，但预期明确未出现且可复现（行为与预期相反，疑似应用缺陷） |
| `partial` | 部分断言已验证，另一部分被有意保留（用户拍板延后维度 / 用例被部分跳过） |
| `blocked` | 路径无法真实建立（前置 / 权限 / 数据 / 会话 / 外部依赖 / 地址不可达任一缺失）——**不是应用 bug** |

```
用例未通过
  ├─ 手动复现：UI 真的没按预期工作？
  │   ├─ 是 → 应用 bug → 判 fail，报告记录，不修源码
  │   └─ 否 ↓
  ├─ 路径根本无法建立？（必需字段/按钮/弹窗/账号/数据缺失，或外部依赖/地址未就绪）
  │   ├─ 是 → blocked（判据：必需控件始终不可用 / 页面不可达 / 必需账号或会话不可用 /
  │   │        无法建立安全测试数据 / 缺外部依赖 / 被测地址不可达）
  │   └─ 否 ↓
  ├─ 仅部分维度被有意保留（用户已确认延后）？
  │   ├─ 是 → partial（备注「已验证 X，保留 Y，保留原因 Z」）
  │   └─ 否 ↓
  └─ flaky → 单次重试（≤1 次），仍不稳定按事实记录
```

**保持 fail（非 blocked）**：控件/页面/账号都存在但行为错——保存/提交/上传/导出/查询结果错误、展示错误数据、状态错误。
**重分类为 blocked**：必需控件始终不可用 / 页面不可达 / 必需账号或会话不可用 / 无法建立安全测试数据 / 缺外部依赖。

### 2.1 意外状态恢复 → blocked 阈值

操作后到达预期之外的页面（错误页 / 首页 / 空白页）时：

1. 先 `browser_snapshot` 当前 URL + 关键元素，确认实际状态。
2. 已知场景按恢复路径处理：401 → 重新登录（有账号用账号，无账号 / 账号失效走「登录态建立」② 手动登录）；导航错误 → `browser_navigate` 直跳目标；弹窗遮挡 → 先关闭再重试。
3. **连续 3 次仍无法恢复到预期状态 → 当前用例判 `blocked`**，备注记录恢复尝试。

**禁止**：无限重试 / 盲点其他按钮"自救" / 跳过预期断言直接判 pass。

### 2.2 整批鉴权熔断（401 雪崩）

执行中若**鉴权失败（401/登录态失效）的用例比例 > 50%**，立即停止剩余用例，整轮标 `CIRCUIT_BROKEN`。
典型根因：测试账号失效 / JWT 漂移 / DB `users` 表被清空 / 后端连不上 DB。处置：复测登录（账号失效可走「登录态建立」② 手动登录重建会话）；失败则提示用户检查账号/环境，**不重跑**；成功视为 flaky 可重跑一次。

## 3. 失败处理铁律

### 3.1 严禁修改源代码

| 情况 | 允许动作 | 禁止动作 |
|------|---------|---------|
| 应用 bug（fail） | 报告中记录 + 三段式备注 | 修改 `src/`、`api/`、`components/` 等任何业务源码 |
| 环境问题 / blocked | 报告标注阻塞根因（环境/前置/数据），等阻塞解除后重跑 | 强行 mock 绕过阻塞、把 blocked 改判为 pass |
| 需求未实现 | 标注失败并记录 | 自行实现该功能 |
| partial | 备注「已验证 X，保留 Y，原因 Z」 | 用 partial 掩盖未做的工作 / 不写保留原因 |

执行阶段**只在被测系统页面内操作**，只读测试用例/需求/环境与业务源码，绝不修改它们，也不改任何配置文件。

### 3.2 应用 bug 事实记录（仅事实，不给修复方案）

记录：测试用例 ID、重现步骤、预期、实际、证据（截图路径）。**禁止**写修复方案/改哪行/优先级/发布与否（属开发范畴）。

## 4. 执行产物（落盘契约）

逐条执行完成后，**落盘逐条结果**到 `/AI_LabTest/report/{任务}/{任务}-{ENV}.results.json`（严格 JSON，机读版；执行产物按任务分目录存放），执行引擎据此**确定性归约**四态计数：

```json
{
  "tests": [
    { "id": "TC-{任务}-001", "title": "用例标题", "status": "pass|fail|partial|blocked",
      "expected": "预期结果", "actual": "实际观察到的现象",
      "evidence": ["截图相对路径或文件名"], "video": "录屏相对路径（可选；未录则省略）", "error": "失败/阻塞的简短原因（pass 留空）" }
  ],
  "notes": "可选：整体说明"
}
```

引擎归约后产出 `/AI_LabTest/report/{任务}/{任务}-{ENV}.run.json`（四态计数 + 逐条状态 + 证据/熔断标记 + 执行时间）——这是**步骤 3 报告的唯一权威事实来源**。

- `status` 只用四态之一；其余值按 `fail` 计。
- 计数与通过率由引擎确定性计算，不要在结果里自报算术。
- **录屏（可选）**：若随附 Playwright MCP 支持录屏 / trace，逐条（或整轮）落盘视频到 `report/{任务}/录屏/`，路径写入该用例 `video`，供报告「执行矩阵」（`test-report.md §2.8`）的「录像」列引用；不支持则省略 `video`、该列填 `—`。**不为录屏而改用脚本**（守 §1.0 铁律）。

**导入导出文件留存**：测试页面的导入/导出功能时，相关文件统一留存到 `/AI_LabTest/report/{任务}/导入导出/`，供用户事后校对：
- **导出（下载）**：下载文件先落浏览器工具的 output-dir（证据目录），执行结束由引擎自动归档到上述目录；`actual` 里写明「已下载 <文件名>」。
- **导入（上传）**：上传所需的测试源文件先写入证据目录（文件名带用例 ID，如 `TC-{任务}-005-导入测试.csv`），再以绝对路径上传；执行结束同样自动归档。

## 5. 边界情况

| 场景 | 处理 |
|------|------|
| 整批因鉴权失效全失败 | 立即停止（§2.2 熔断），提示用户检查测试账号/环境 |
| 数据创建污染被测系统 | 用例内自行清理；如已污染，提示用户手动重置 |
| 被测地址不可达 / 应用未启动 | 不进入执行，先排查环境（§0.3），提示用户 |
| 执行超时（单任务 > 30 分钟） | 中断，提示用户精简范围 |
